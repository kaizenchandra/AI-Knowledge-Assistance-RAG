# Security assessment and threat model

Continuation: ingress now buffers bounded request bodies before multipart parsing (including requests without Content-Length), extraction runs in a credential-free child with Linux resource limits and a wall deadline, and ClamAV scanning is required outside development. Clean/EICAR scanning was exercised against a real local daemon. Malware enters a non-searchable quarantined state. This narrows the original open gates below; it does not provide full network/filesystem sandboxing or certify production scanner freshness/availability. Previous assistant messages with revoked/deleted/outdated citations are omitted from model history.

Assets: source documents, embeddings, checkpoints, conversation history, tenant membership and provider credentials. Trust boundaries: browser→API, API→database/storage, worker→untrusted parser input, graph→external provider. Retrieved text and model responses are untrusted.

Implemented controls: bearer validation (RS256, issuer/audience/expiry/subject), server-derived membership roles, scoped resource lookups, workspace membership, owner-only conversation access, tenant vector namespaces, SQL reauthorization of vector matches and citations, immediate deletion tombstones, administrator approval with expiry/receipt, deterministic graph bounds, generated storage keys, bounded extraction/archive expansion, no shell/SQL/URL agent tool, parameterized SQL, plain-text React output, loopback-only local ports and random ignored development secrets. Redis limits fail closed. Checkpoints and SQL store content; default structured request logs omit content/tokens.

Unclosed production gates: full OIDC browser flow, refresh and immediate token revocation; production scanner updates/failover; parser network/filesystem sandbox; concurrent-upload backpressure; per-tenant storage/token quotas; PostgreSQL RLS or equivalent independent enforcement; per-document ACLs; scheduled retention; source object reconciliation; security scanning and penetration review; dependency/image policy; encryption/TLS deployed verification; cloud IAM review. Production configuration checks are necessary, not a production-readiness claim.

Injection defense does not rely solely on prompts: graph cannot execute an arbitrary tool, tenant scope comes from verified application data, and reprocess approval is checked in SQL. The model may still produce misleading text; structural citations do not certify groundedness. Treat displayed token stream as provisional until final validation.
